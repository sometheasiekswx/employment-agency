# Reconcile external edits and preserve history during migration

On 29 October 2026, the owner confirmed that the shared app should detect master-resume changes inside the selected career workspace and present proposed fact updates and conflicts for confirmation before using the changes in new applications. Supplementary facts remain available. Existing application versions are preserved; regeneration happens only when requested and creates a new version. The default workspace is inside the source installation, while another folder remains an available secondary setup option.

Direct edits to generated CVs, cover letters or source files are detected and flagged. The user can validate the changes as a new draft version, with affected PDFs and email attachments rebuilt where supported and review required before the changed version becomes ready. Previously verified files must remain recoverable. Recovery snapshots serve preservation, not a second active package store; external edits must never silently redefine submitted documents.

The agreed migration includes the current application state and the legacy review queue. Preserve unique documents, decisions and provenance, and flag conflicting or uncertain historical records. Retire obsolete application code from the personal workspace only after backup, restore and migration checks pass, preserving the old implementation in a recovery snapshot. This is a migration contract, not evidence of completed migration or authorisation to publish personal data.
