# Bounded job discovery

The local Search page and agents use one search-only workflow. A run can refresh selected employer boards and public feeds or inspect public URLs the user or agent supplies. Reuse the active search profile when ranking newly found roles. Return page text, source links and uncertain leads for review. Persist structured vacancies with their original links, source identities and dates. [Architecture decision](../../docs/adr/0014-local-discovery-with-bounded-fallbacks.md)

- Support Greenhouse, Lever, SmartRecruiters, Ashby and Workable employer feeds, plus We Work Remotely RSS and the public Remotive API with source attribution. Extract JobPosting metadata, links, and readable text from ordinary pages. Follow relevant links from a careers index or sitemap within the source site or to a recognised employer feed under page and time limits.
- Try local direct HTTP first. Use a local, isolated Playwright browser for permitted public JavaScript pages when available. An explicit opt-in can use basic Firecrawl scraping for up to two public pages per search within the free limits. Keep browser sessions, career facts, documents and credentials out of third-party requests.
- Show results as sources finish. By 25 seconds show the results and remaining sources. Stop waiting for new results after 90 seconds. Stop keeps already committed results and prevents later imports. A blocked, incomplete or failed source retains the last successful records and timestamps. Only a complete employer snapshot can establish that a posting disappeared.
- Dedupe by source posting ID, listing URL and existing confirmed vacancy relationships. Keep existing bookmarks, removals, submissions and career evidence. Respect company cooldowns and confirmed exclusions. Distinguish a new workspace record from a newly dated posting.
- Verify against a sample of at least 30 real public URLs across at least 15 sites. Cover live feeds, Cambodian boards and employers, remote listings, static and JavaScript pages. Compare extracted fields against the originals and document unavailable sources and any gaps. Use controlled tests for blocked pages, transient failures, stale data, duplicates, browser boundaries, stop and deadline races. Keep live verification separate from CI.

The local app owns the new workflow. Discovery can be started on demand through the Search page and the local API or CLI. Application preparation, scheduled searches and installing into the private workspace require their existing separate workflows.
