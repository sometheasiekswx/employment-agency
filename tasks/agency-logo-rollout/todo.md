# Agency identity rollout

Plan and acceptance criteria: [plan.md](plan.md). The boxes record readiness before the release commit. See [verification.md](verification.md) for local results, [Checks](https://github.com/sometheasiekswx/employment-agency/actions/workflows/check.yml) for the push and deploy results, and the [live marker](https://employment-agency-demo.vercel.app/release.json) for the deployed revision. The local release record and private cutover evidence stay outside shared Git.

- [x] **A1 — Web identity and install metadata.** Copy exact kit assets, theme the outlined wordmark, replace favicon, touch, pinned and PWA assets, and add the manifest. Preserve product name/navigation. Verify both themes, saved/System appearance, 320px layout, metadata responses and source hashes.
- [x] **A2 — Native launcher assets.** Replace existing iOS and Android resources without changing app IDs/origins/signing. Compile with available toolchains, inspect simulator/emulator icons where available, and record physical-device gaps. Depends on asset selection in A1.
- [x] **A3 — Current documentation and media.** Update README/DESIGN/current branding descriptions, recapture all current fictional walkthroughs and pass the showcase checker. Preserve historical evidence. Depends on A1.
- [x] **A4 — Shared candidate verification and review.** Run frontend/Python/export browser/public-preview checks and installed-wheel proof; independently review the final diff and resolve findings. Record exact candidate and asset evidence. Depends on A1–A3.
- [x] **A5 preflight — Recoverable private candidate.** Verify the current pin/process; export with supported operations; restore into a new protected directory; compare state and immutable documents; test normal shared-wheel/highlight compatibility. Do not mutate private records for testing. Backup preparation may start early; candidate acceptance depends on A4.
- [ ] **A6 public — Shared main and live demo.** Push the reviewed commit, wait for required CI and automatic release, verify exact public commit/assets and desktop/mobile appearance. No credentials or store release. Depends on A4 and A5 preflight.
- [ ] **A5 cutover — Running private installation.** Refresh backup evidence if state changed; switch only the identified runtime; verify loopback and private HTTPS, records and highlights; update private pin/docs after acceptance and retain rollback. Depends on the exact reviewed shared revision and A5 preflight.
- [ ] **Closeout — Evidence and limitations.** Record source/public/private outcomes, native build/runtime coverage and any remaining physical-device or browser-cache limitation. Keep private evidence out of shared Git and report no broader publication than was performed.
