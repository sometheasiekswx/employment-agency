# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

People preparing and reviewing their own career applications. The owner uses the app locally with a separate private career workspace. Developers need conventional, readable React/Next.js code and shared Python services.

## Product Purpose

Turn confirmed career evidence and job requirements into reviewable application documents. Success means users can inspect evidence, edit a new draft, find exact document versions, and record their own decisions without losing data.

## Operating Context

A local Python server serves a static React/Next.js interface and application API. A separate invite-only hosted pilot uses the same services with authenticated cloud storage. Career facts, job records, decisions and documents are private data, never build inputs.

## Capabilities and Constraints

Preserve all existing local and hosted workflows, including setup/folder selection, career evidence and master reconciliation, profiles, discovery/ranking, bounded preparation, editing/versioning, comments/decisions, history, export and recovery. Hosted restrictions remain explicit. Drafting and manual Submitted decisions never send anything. The local Apply For Me preview permits external sending/submission only after separate exact per-application approval. Hosted execution remains disabled. No unapproved paid requests, cloud upload of local workspaces or private installation upgrade.

The owner explicitly confirmed product/workflow preservation for this redesign. Python services and storage remain authoritative. Submitted snapshots and canonical document links retain their integrity rules. Decision queues show one current version per job; submitted snapshots take precedence, while all document versions remain in History. Empty, busy, success, error, permission and reduced-motion states must remain usable.

## Brand Commitments

Keep the Employment Agency product name and truthful review-first language. The visible wordmark is Agency, paired with the approved rounded briefcase/person mark. The user selected Concept A revision 2: the Orax-inspired charcoal workspace, contextual desktop sidebar, restrained lavender selections, pink-to-lavender primary actions and locally hosted Inter typography. This replaces the former white and sky-blue direction. Discover presents opportunities by chosen location; selecting a role opens a docked inspector on desktop and an expandable sheet on mobile without losing the shortlist context. Use real workspace counts and evidence; do not carry illustrative employer, candidate or progress data into production. Confirmed evidence and reviewed states use green, requirements needing review use amber, rejection and errors use red, and submitted records remain neutral and explicitly labelled. Public demonstrations stay visibly fictional. No fabricated career claims, metrics, qualifications or customer evidence.

## Evidence on Hand

Existing Python, frontend and browser acceptance suites; fictional browser fixtures; documented local/hosted boundaries and systems design. Public demos use marked fictional candidate records and sourced public job metadata. Real private career data never belongs in screenshots, tests or public documentation. Live cloud acceptance is distinct from fake-provider test results.

## Product Principles

- The user controls confirmation, document versions and submission decisions.
- Personal data remains separate from reusable application software.
- Shared server rules govern both interfaces.
- Preserve drafts and make failures recoverable.
- Make the next useful action easy to find without hiding important warnings.
