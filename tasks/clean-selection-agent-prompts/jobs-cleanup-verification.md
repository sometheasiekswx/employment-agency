# Reversible Jobs cleanup

The shared SQLite transaction compares effective company-round evidence before and after a write. Two dated confirmations for distinct vacancies in a qualifying active round move the employer's remaining Jobs to Removed. Manual review, self-application confirmation, legacy delivery, connected execution and receipt reconciliation all use this write boundary. The ordinary application queue and snapshot publish the removal events with the rest of the transaction.

Two pending roles, a manual pause with one confirmed vacancy, and undated history alone never qualify. To apply choices, submitted vacancies and equivalent listings, past removals, and protected work stay in place. An unchosen draft follows its role to Removed and keeps its complete version and documents. The effect survives expiry and history correction. Use Restore to put a role back.

If a previously auto-removed role is later confirmed as submitted, the exact submission appears under Submitted. A verified equivalent with no submission of its own does not create another Submitted entry. The original automatic event stays in the workspace audit and becomes active again if the confirmation is corrected. An intentional manual removal keeps its existing priority.

## Existing-round operation

Use the installed CLI with the app stopped, or send the same JSON through the local app's protected POST interface. Check the returned `workspace` and `workspace_id` against the intended local SQLite workspace.

~~~sh
printf '%s\n' '{}' | employment-agency --workspace "$WORKSPACE_PATH" action company-jobs-cleanup-preview
employment-agency --workspace "$WORKSPACE_PATH" action company-jobs-cleanup-apply --input reviewed-cleanup.json
~~~

`reviewed-cleanup.json` contains `{"confirmed":true,"fingerprint":"FINGERPRINT_FROM_THIS_WORKSPACE_PREVIEW"}`. Use a preview generated by the same workspace where apply will run. A restored rehearsal has a new workspace identity and fingerprint even when its candidate and skipped lists match.

Preview returns `workspace`, `workspace_id`, `companies`, `candidates`, `skipped` and `fingerprint`. `companies` identifies each qualifying employer, its confirmed pair of `vacancy_ids` and `cooldown_until`. Each candidate carries `job_id`, `title`, `employer_id`, its own `vacancy_id`, the qualifying `vacancy_ids`, `listing_sha256` and `removal_id`. Skipped entries carry the exact job ID and title, a code and a message, plus verified employer information or possible employer IDs for an unresolved match.

Apply recalculates the plan under the SQLite write transaction. If the reviewed scope has changed, it rejects with `company_jobs_cleanup_changed` and requests a fresh preview. On success it returns the reviewed scope with `removed_count`. The listed `candidates` are the removal events applied in that transaction. If the response is lost, preview again to verify which removals exist. An explicit Restore keeps the same removal event and prevents that round from adding another one for that role. Protected and unresolved candidates can be reviewed again explicitly. The event type `company_jobs_cleanup_skipped` records work left alone after a qualifying write.
