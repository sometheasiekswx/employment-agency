# Demo workspace and walkthrough

The public demo uses **Alex Morgan**, a fictional New York software engineer. Harbor Metrics, Northstar Transit, Hudson College, employment dates, experience, education and review decisions are invented sample material. They do not describe a real person's career. The original sample resume is bundled as `employment_agency/demo_data/resume.txt`, imported and reconciled through the same validated operations as other resumes. Generated files contain sample material and must not be submitted.

The jobs are real employer-board metadata snapshots, not invented vacancies. The included snapshot was checked on **31 October 2026, Melbourne time** (the exact UTC timestamp is in `jobs.json`). It contains 13 software engineering listings from MongoDB and Datadog, including New York, multi-office New Jersey/Princeton and Toronto roles. Public titles, locations, URLs and technical keywords are retained; descriptions are short metadata summaries rather than copied adverts. Availability, salary and work rights are not invented. Recheck the original posting before acting; a saved snapshot cannot guarantee a role remains open.

Sources: [MongoDB employer board](https://boards-api.greenhouse.io/v1/boards/mongodb/jobs), [Datadog employer board](https://boards-api.greenhouse.io/v1/boards/datadog/jobs). Exact role URLs and the retrieval time are in [the bundled snapshot](../employment_agency/demo_data/jobs.json). These employers do not endorse the project.

## Start and reopen

After installing the release wheel or building the source:

```sh
.venv/bin/python -m employment_agency demo demo-workspace --serve
```

Open **http://127.0.0.1:8770**. Windows uses `.venv\Scripts\python`. No network, paid model, provider key or external account is used to seed the demo. It creates 15 confirmed sample facts, three profiles, 13 job records and 10 application packages, including PDFs, editable Word documents, evidence and review comments. Those counts come from the shipped data, not vanity metrics.

An existing destination is refused. To reopen a marked demo without replacing edits:

```sh
.venv/bin/python -m employment_agency demo demo-workspace --open --serve
```

The header identifies the fictional profile. The demo server keeps its configuration under the demo's `.runtime/` and does not replace your remembered personal-workspace location. `--open` checks the demo markers before opening a store; it rejects ordinary personal workspaces. Creating the demo stages all documents before publishing the new destination. Normal package validation, integrity checks and workspace locks still apply.

## Reproduce the GIF

Install development dependencies and build the production frontend first. Create/start a disposable demo on port 8777:

```sh
.venv/bin/python -m employment_agency demo demo-workspace --serve --port 8777
```

In another terminal in the source checkout:

```sh
node scripts/capture-demo.cjs
.venv/bin/python scripts/build-demo-gif.py
```

The capture script refuses a non-loopback URL or an unmarked/non-sample identity. It uses real browser actions to show the queue, Toronto filter, generated PDF preview, career evidence, ranked real jobs, preserved history and mobile layout. It asserts the expected job/application counts and checks for page errors. The image builder uses Pillow, already included through the document renderer's dependencies. No media is generated by AI. The GIF is seven real screenshots held long enough to read; it is a compressed workflow walkthrough, not a real-time recording. The README supplies a static image for reduced-motion viewers and a static-preview link.

Capture files: `output/demo-frames/manifest.json` (frames, durations and source), `docs/demo.gif`, `docs/preview.png`, `docs/evidence/0.5-desktop.png` and `0.5-mobile.png`. Source provenance is retained in `docs/evidence/0.5-media-origin.txt`.

A maintainer can explicitly refresh public metadata with `python scripts/refresh-demo-jobs.py`. That operation makes bounded read-only employer-board requests; it is never run at app startup, during seeding or by automated tests. Review changed jobs, keywords, dates, demo counts and screenshots before publishing an updated snapshot.
