# Security and privacy

The local application runs for one user and binds only to 127.0.0.1. It validates Host/Origin and mutation tokens, uses a restrictive content policy and escapes rendered text. The separate hosted pilot has the authentication and storage boundaries described below. Keep the workspace and its backups private. Other processes running as your OS user can read it; there is no encryption-at-rest claim.

Public job URL retrieval requires HTTPS, rejects non-global addresses, pins the validated IP for the TLS connection and rechecks each redirect. Fetches have size/time limits. Adverts and imports are data, never instructions. TeX imports are extracted as text without execution. DOCX expanded size and PDF page counts are bounded; parsing third-party files still depends on the document libraries, and only trusted local users should import files.

AI provider keys are environment-only and are not in export schemas. The optional local Gmail connection stores OAuth credentials in macOS Keychain. Browser sessions, Codex sign-in and connection state stay outside portable workspace exports and Git. Provider consent is scoped and revocable; restore clears grants. API errors omit response bodies. Export archives are checksummed and restored to new destinations with path/size checks. File downloads are allowlisted; packages preserve the exact reviewed version.

The current local SQLite app supports **Apply for me** through a verified Codex runtime and available application channel. Starting authorizes preparation, necessary disclosure and submission for the named role; saving, copying instructions, drafting or recording a manual submission does not. The service binds authority to the workspace and path, employer, destination and exact documents; it expires after 24 hours and is not replayable from a restored copy. Missing information, unsupported forms and uncertain delivery pause for help. An uncertain external outcome must be reconciled before retrying. Earlier `apply-*` delivery attempts retain their original exact final-approval rules. Hosted and public-demo execution are disabled. See the [current authorization decision](docs/adr/0016-authorize-role-submission-when-starting-agent.md) and [channel support and limitations](docs/apply-for-me.md).

No application telemetry or scheduler is included. Remote exposure, new external-action channels and changes to agent execution require a corresponding threat-model review; do not treat drafting or a Reviewed status as submission approval.

Report vulnerabilities privately through GitHub private vulnerability reporting when enabled. Avoid placing personal data, API keys or workspace exports in issues.


New local workspaces use SQLite database schema 7. The live database is ignored by Git; the app publishes a schema-3 readable snapshot and verifies it before restore. Legacy JSON schema-2 workspaces remain supported with fewer capabilities. Both keep local provider permissions outside portable records. Workspace switching is refused during preparation, delivery or connected application work; a successful switch closes discovery and rotates the browser mutation token, rejecting writes from an old tab. The software checkout itself cannot be selected as a personal workspace; choose an external directory or the ignored `workspace/` subfolder. Application paths reject traversal and symlink components. Named document routes check registered manifests and file hashes before serving bytes.

Private remote access uses the explicit Tailscale Serve origin and owner checks described in [the remote-access runbook](docs/tailscale.md). Loopback binding alone is not authorization for a proxy. Do not expose the local server through public Funnel or an unverified reverse proxy.

The static public showcase is a separate publishing boundary. Its reviewed catalog and explicitly approved public résumé are public; sample decisions are simulated. Visitor résumé imports and new drafts remain in tab memory and are not sent to an application API. Loading the site, downloading its public assets or following an employer link still makes ordinary browser network requests. Public-demo builds must never load a private career workspace. See [demo data and privacy](docs/demo.md).

Only an explicitly enabled local master template is compiled; imports alone never trigger compilation. LaTeX runs with shell escape disabled, restrictive input/output settings, a timeout and temporary build directory. This is not an operating-system sandbox: enable local templates only when you trust their contents. External document edits require validation as a new draft, and verified originals are retained for recovery. Backups include private data and must be stored privately.

## Hosted pilot boundary

The hosted WSGI entrypoint is separate from the loopback CLI. It verifies Supabase sessions, confirmed Google identity and an explicit server allowlist before any workspace operation. All database and private-bucket client grants are denied; the server-only service-role key performs owner-scoped operations. Consequently, the application authentication/owner-scoping boundary is critical: RLS does not constrain a service-role request. Cross-owner tests cover this application boundary; deployed SQL policies and OAuth still need live verification before launch.

Snapshots are uploaded under authenticated account UUIDs. A Postgres compare-and-swap publishes a new revision only when the old revision matches and quotas permit. Account deletion blocks commits before removing objects and Auth identity. No local filesystem switching, TeX execution, paid AI, automatic email, or application sending is exposed by the hosted endpoint. Supabase configuration and secrets belong in provider dashboards; the public config endpoint returns only URL and anonymous key after the pilot release gate is enabled.
